# 本地网页归档整理与管理工具

## 项目背景

当前网页归档位于：

```text
/Users/wankun/allbak/网页
```

这些文件的首要价值是“即使原网页失效，仍能在本地找回内容”。因此，本项目不以压缩空间或追求完美分类为第一目标，而以以下目标为准：

1. 原始内容不丢失、可回退。
2. 能按标题、正文、来源、日期、主题快速检索。
3. 新归档的网页可以低成本进入系统。
4. 分类不再完全依赖物理目录。
5. 为后续开发本地网页管理工具准备稳定的数据约定。

## 当前阶段

方案已于 2026-08-15 确认，开始实施只读索引阶段。仍不移动、不重命名、不删除原目录中的任何文件。

已确认决策：

- 主分类采用 8 类设计。
- 当前网页文件不设置私密正文扫描限制。
- 采用“先建索引、暂不搬文件”的路线。

### 本地管理界面

```bash
cd /Users/wankun/github/my-project/web-archive-manager
python3 app.py
```

更新代码后必须重启 Python 服务。只刷新浏览器会加载新前端，但不会重新加载正在运行的后端代码；页面会检测API版本并提示重启。

浏览器打开 `http://127.0.0.1:8765`，可使用：

- 中文标题与正文检索。
- 按 8 个主分类、档案类型筛选。
- 按来源域名、保存日期范围和阅读状态组合筛选，并切换相关度、时间、修改时间或文件大小排序。
- 查看来源、保存时间、本地路径和正文预览。
- 人工修正主分类和标签。
- 查看自动分类置信度与依据，并集中处理待确认建议。
- 收藏网页、维护已读/待读状态并添加个人备注。
- 在CSP沙箱中安全预览HTML，或用系统默认应用打开原始归档。
- 查看重复内容、扫描失败、正文提取失败和源文件缺失维护队列，并从页面触发只读增量同步。
- 按常用标签筛选，修订档案标题与原始网址，并在 Finder 中定位本地原文件。
- 导出或合并人工数据、创建 SQLite 本地快照，并生成索引健康报告。

应用只监听本机地址，不上传网页内容，不移动归档原件。
人工分类、标签、收藏、阅读状态和备注会写入本地 `data/user-overrides.json`，应用重启或重新生成索引后仍会重新应用。

### 数据保全

维护抽屉中的“数据保全袋”提供四项本地操作：

- 导出人工数据：下载带格式版本号的 JSON，不包含网页正文。
- 导入并合并：只接受当前格式版本；同一资产使用导入值，其他本地记录保留，未知资产跳过。
- 创建本地快照：使用 SQLite 在线备份生成 `data/backups/{backup_id}/catalog.sqlite`，同时保存人工数据包。
- 生成健康报告：检查 SQLite 完整性、外键、孤立正文、全文索引数量和维护队列。

`data/backups/` 仅保留在本机，不提交到 Git。

## 数据与 Git

以下内容默认不提交到 GitHub：

- `data/catalog.sqlite`：包含本机网页正文索引和绝对路径。
- `data/user-overrides.json`：个人分类、标签、收藏、阅读状态和备注。
- `reports/inventory.jsonl`：逐文件资产清单。

克隆代码到新机器后，需要先运行 `build_catalog.py` 和 `build_search_index.py` 重新生成本地数据。

## 自动分类

分类器只填充未分类内容，不覆盖既有分类和人工修改。建议先预览：

```bash
python3 scripts/classify_catalog.py
```

确认 `reports/classification-summary.md` 后应用：

```bash
python3 scripts/classify_catalog.py --apply
```

## 核心结论

不建议直接把 3.4GB 文件一次性“重新分目录”。更稳妥的方式是：

```text
原始文件只读保留
        ↓
生成资产清单与内容指纹
        ↓
抽取标题、正文、来源、保存时间等元数据
        ↓
使用“主分类 + 多标签”建立逻辑视图
        ↓
确认无误后，再决定是否进行物理目录迁移
```

这能避免 HTML、MHTML、笔记和附件在批量移动中损坏，也能让未来的管理工具直接复用索引数据。
